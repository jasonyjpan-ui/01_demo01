## 功能測試場景

### 場景 1: 購物車價格變動提示

**目標**: 驗證購物車中的項目價格變動能被正確檢測和顯示

#### 步驟:

1. **添加項目到購物車**
   - 點擊「火腿蛋吐司」的「+」按鈕
   - 打開購物車抽屜，確認項目已添加（¥40）

2. **使用 REST 客户端更新菜單**
   
   使用 test_01.rest 或 test_02.rest 中的端點：
   
   ```http
   PATCH http://localhost:3000/api/menu/1
   Content-Type: application/json
   
   {
     "price": 50,
     "version": 1,
     "changeReason": "材料成本上升"
   }
   ```

   或使用 curl:
   ```bash
   curl -X PATCH http://localhost:3000/api/menu/1 \
     -H "Content-Type: application/json" \
     -d '{"price": 50, "version": 1, "changeReason": "材料成本上升"}'
   ```

3. **刷新頁面或重新打開購物車**
   - 購物車應該顯示 **「💰 價格變動提示」**
   - 顯示: 「火腿蛋吐司 ¥40 → ¥50（材料成本上升）」

4. **驗證視覺效果**
   - 價格變動項目使用**橙色邊框**
   - 顯示舊價格和新價格
   - 顯示變更原因

#### 預期結果:
✅ 購物車中檢測到價格變動
✅ 正確顯示舊價格和新價格
✅ 顯示變更原因

### 場景 2: 訂單提交時版本不匹配

**目標**: 驗證提交訂單時版本不匹配能被檢測並顯示詳細錯誤信息

#### 步驟:

1. **添加項目到購物車（第二個項目）**
   - 添加「起司豬排堡」(原價 ¥65)
   - 購物車應包含兩個不同的項目

2. **更新第二個項目的版本**
   ```bash
   curl -X PATCH http://localhost:3000/api/menu/2 \
     -H "Content-Type: application/json" \
     -d '{"price": 75, "version": 1, "changeReason": "新鮮食材調整"}'
   ```

3. **不刷新頁面，直接點擊「送出訂單」**
   - 前端仍然持有舊版本的菜單項目快照
   - 後端會檢測版本不匹配

4. **驗證錯誤提示模態框**
   - 應看到 **「⚠️ 訂單提交失敗」** 模態框
   - 顯示錯誤信息: "Menu version mismatch: order contains stale item data"
   - 顯示詳細的 **「受影響的項目」** 清單
   - 列出: 「起司豬排堡（菜單已更新）¥65 → ¥75」
   - 顯示 **「建議」** 步驟
   - 提供 **「🔄 刷新菜單重試」** 按鈕

5. **點擊「🔄 刷新菜單重試」**
   - 頁面應刷新菜單
   - 重新加載購物車
   - 現在購物車中應該顯示新價格

6. **再次點擊「送出訂單」**
   - 訂單應成功提交
   - 購物車清空

#### 預期結果:
✅ 版本不匹配被正確檢測
✅ 返回 HTTP 409 狀態碼
✅ 錯誤模態框顯示詳細信息
✅ 「刷新菜單重試」按鈕功能正常
✅ 刷新後訂單提交成功

### 場景 3: 失效項目移除

**目標**: 驗證購物車中的失效項目能被正確識別和移除

#### 步驟:

1. **添加一個項目到購物車**
   - 添加「鮪魚蛋吐司」(ID: 3)

2. **刪除這個菜單項目**
   ```bash
   curl -X DELETE http://localhost:3000/api/menu/3
   ```

3. **打開購物車**
   - 應看到 **「⚠️ 購物車失效警告」**
   - 列出失效項目: 「鮪魚蛋吐司（菜單項目已不存在）」

4. **點擊「移除失效項目」按鈕**
   - 該項目應從購物車中移除
   - 購物車總金額更新
   - 警告消失

5. **點擊「送出訂單」**
   - 訂單應成功提交（因為沒有失效項目）

#### 預期結果:
✅ 失效項目被正確檢測
✅ 顯示紅色邊框警告
✅ 「移除失效項目」按鈕有效
✅ 移除後訂單可正常提交

### 場景 4: 版本歷史查詢 API

**目標**: 驗證版本歷史查詢端點返回正確信息

#### 步驟:

1. **進行多次菜單更新**
   ```bash
   # 更新 1
   curl -X PATCH http://localhost:3000/api/menu/1 \
     -H "Content-Type: application/json" \
     -d '{"price": 45, "version": 1, "changeReason": "首次調整"}'
   
   # 更新 2
   curl -X PATCH http://localhost:3000/api/menu/1 \
     -H "Content-Type: application/json" \
     -d '{"price": 55, "version": 2, "changeReason": "再次調整"}'
   ```

2. **查詢版本歷史**
   ```bash
   curl http://localhost:3000/api/menu/1/history | jq .
   ```

3. **驗證回應格式**
   ```json
   {
     "data": [
       {
         "version": 3,
         "name": "火腿蛋吐司",
         "price": 55,
         "previousPrice": 45,
         "changeReason": "再次調整",
         "changedAt": "2024-12-19T10:30:00Z"
       }
     ]
   }
   ```

4. **查詢不存在的項目**
   ```bash
   curl http://localhost:3000/api/menu/999/history
   ```
   
   應返回 404:
   ```json
   {
     "error": "Menu item not found"
   }
   ```

#### 預期結果:
✅ 返回正確的版本信息
✅ 包含變更原因和時間戳
✅ 不存在項目返回 404

## API 測試清單

### 驗證菜單 CRUD 操作

```bash
# 創建新菜單項目
curl -X POST http://localhost:3000/api/menu \
  -H "Content-Type: application/json" \
  -d '{
    "name": "新項目",
    "price": 50,
    "category": "餐點",
    "description": "測試項目",
    "image_url": "/imgs/menu/test.webp"
  }'

# 獲取當前菜單
curl http://localhost:3000/api/menu/current | jq .

# 更新菜單帶變更原因
curl -X PATCH http://localhost:3000/api/menu/1 \
  -H "Content-Type: application/json" \
  -d '{
    "price": 60,
    "version": 1,
    "changeReason": "價格調整"
  }'

# 查詢版本歷史
curl http://localhost:3000/api/menu/1/history | jq .

# 刪除菜單項目
curl -X DELETE http://localhost:3000/api/menu/1
```

### 驗證訂單操作

```bash
# 創建訂單
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{"userId": "user1"}'

# 更新訂單項目
curl -X PATCH http://localhost:3000/api/orders/1 \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "user1",
    "itemId": 1,
    "qty": 2
  }'

# 獲取當前訂單
curl "http://localhost:3000/api/orders/current?userId=user1" | jq .

# 提交訂單（可能失敗版本不匹配）
curl -X POST http://localhost:3000/api/orders/1/submit \
  -H "Content-Type: application/json" \
  -d '{"userId": "user1"}'

# 查詢訂單歷史
curl "http://localhost:3000/api/orders/history?userId=user1" | jq .
```

## 常見問題排查

### 問題 1: 購物車驗證組件未顯示

**症狀**: 價格變動後，購物車中看不到 CartValidation 組件

**排查步驟**:
1. 打開開發者工具 (F12) 控制台
2. 查找是否有 TypeScript 錯誤
3. 確認 `currentOrder` 狀態已正確保存
4. 刷新頁面後重新打開購物車

### 問題 2: 訂單提交成功但應該失敗

**症狀**: 購物車中的菜單項目版本過時，但訂單仍然提交成功

**排查步驟**:
1. 確認使用的是最新的前端構建 (`npm run build`)
2. 檢查後端是否正確更新了菜單版本
3. 確認瀏覽器緩存已清除 (Ctrl+Shift+Delete)

### 問題 3: 版本歷史端點返回 501

**症狀**: `/api/menu/:id/history` 返回 HTTP 501 "Not Implemented"

**排查步驟**:
1. 確認使用的儲存後端支持版本歷史 (PgStore 或 JsonFileStore)
2. 檢查 STORE_DRIVER 環境變量
3. JSON 儲存應返回當前版本信息
