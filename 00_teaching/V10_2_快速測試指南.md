# V10.2 快速測試指南：完整菜單版本化模型

本指南用來驗證 V10.2 的核心行為：菜單項目採用完整版本化模型。更新菜單時不覆蓋舊資料，而是建立新版本；目前菜單只顯示最新版；歷史 API 可查完整版本列表；訂單送出時會擋下過期菜單版本。

## 啟動方式

### JSON store

```bash
cd bf1042
STORE_DRIVER=json npm run dev
```

Windows PowerShell 可用：

```powershell
cd bf1042
$env:STORE_DRIVER = "json"
npm run dev
```

```bash

```

```powershell

npm run dev
```

## 重要概念

V10.2 現在採用保守版完整版本化模型：

- `id`：每一個版本都有自己的 numeric id。
- `logicalId`：同一個菜單品項共用的邏輯 id。
- `entityId`：同一個菜單品項共用的實體識別。
- `version`：版本號，從 1 開始遞增。
- `isCurrentVersion`：是否為目前有效版本。
- `supersedes`：新版本取代哪一個舊版本 id。
- `previousPrice`：若價格有變更，記錄上一版價格。
- `changeReason`：本次變更原因。

## 測試 1：查詢目前菜單

```bash
curl http://localhost:3000/api/menu/current
```

預期：

- 每個品項都有 `id`、`logicalId`、`entityId`、`version`。
- 回傳資料只包含 `isCurrentVersion !== false` 的版本。
- 初始資料通常是 `version: 1`。

## 測試 2：更新菜單會建立新版本

先更新 ID 1 的價格：

```bash
curl -X PATCH http://localhost:3000/api/menu/1 \
  -H "Content-Type: application/json" \
  -d '{"price": 45, "version": 1, "changeReason": "第一次調價"}'
```

預期：

```json
{
  "data": {
    "id": 13,
    "logicalId": 1,
    "version": 2,
    "isCurrentVersion": true,
    "supersedes": 1,
    "previousPrice": 40,
    "changeReason": "第一次調價"
  }
}
```

注意：`id` 會變成新的版本 id，不一定是 `13`；但 `logicalId` 會保留為 `1`。

## 測試 3：再次更新新版，產生第三版

請使用上一個 response 回來的新 `id` 和 `version`。假設新 id 是 `13`：

```bash
curl -X PATCH http://localhost:3000/api/menu/13 \
  -H "Content-Type: application/json" \
  -d '{"name": "新版測試品項", "version": 2, "changeReason": "修改品名"}'
```

預期：

- 回傳新 `id`。
- `logicalId` 仍是 `1`。
- `version` 變成 `3`。
- `supersedes` 指向上一版 id，例如 `13`。

## 測試 4：history API 回完整版本列表

假設第三版 id 是 `14`：

```bash
curl http://localhost:3000/api/menu/14/history
```

預期：

```json
{
  "data": [
    {
      "id": 14,
      "logicalId": 1,
      "version": 3,
      "isCurrentVersion": true,
      "supersedes": 13,
      "changeReason": "修改品名"
    },
    {
      "id": 13,
      "logicalId": 1,
      "version": 2,
      "isCurrentVersion": false,
      "supersedes": 1,
      "previousPrice": 40,
      "changeReason": "第一次調價"
    },
    {
      "id": 1,
      "logicalId": 1,
      "version": 1,
      "isCurrentVersion": false
    }
  ]
}
```

重點：

- history 必須回多筆。
- 排序為新版本在前。
- 舊版本必須保留。

## 測試 5：current menu 不顯示舊版本

```bash
curl http://localhost:3000/api/menu/current
```

預期：

- 同一個 `logicalId` 只會出現一筆。
- 舊 id 例如 `1` 不應再出現在 current menu。
- 新版 id 例如 `14` 會出現在 current menu。

## 測試 6：舊版 version 更新會回 409

如果 ID 1 已經不是 current version，再用它更新：

```bash
curl -X PATCH http://localhost:3000/api/menu/1 \
  -H "Content-Type: application/json" \
  -d '{"price": 99, "version": 1, "changeReason": "舊版更新測試"}'
```

預期：

```json
{
  "error": "Menu item version mismatch"
}
```

HTTP status 應為 `409`。

## 測試 7：訂單送出時擋下過期菜單版本

建立訂單：

```bash
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{"userId": "0001"}'
```

假設訂單 id 是 `1`，把目前菜單 ID 2 加入訂單：

```bash
curl -X PATCH http://localhost:3000/api/orders/1 \
  -H "Content-Type: application/json" \
  -d '{"userId": "0001", "itemId": 2, "qty": 1}'
```

接著更新菜單 ID 2：

```bash
curl -X PATCH http://localhost:3000/api/menu/2 \
  -H "Content-Type: application/json" \
  -d '{"price": 69, "version": 1, "changeReason": "送出前調價"}'
```

送出舊訂單：

```bash
curl -X POST http://localhost:3000/api/orders/1/submit \
  -H "Content-Type: application/json" \
  -d '{"userId": "0001"}'
```

預期 HTTP status 為 `409`：

```json
{
  "error": "Menu version mismatch: order contains stale item data",
  "details": {
    "staleItems": [
      {
        "id": 2,
        "name": "...",
        "orderedPrice": 65,
        "currentPrice": 69,
        "reason": "菜單已更新"
      }
    ]
  }
}
```

重點：

- `orderedPrice` 是加入訂單當下的價格。
- `currentPrice` 是目前最新版價格。
- 後端會透過 `logicalId` 找到目前版本。

## 測試 8：DELETE 是下架 current version

```bash
curl -X DELETE http://localhost:3000/api/menu/3
```

預期：

- 回傳被下架的 current version。
- `/api/menu/current` 不再顯示該版本。
- `/api/menu/3/history` 仍查得到歷史資料。

- [ ] 新版本 `version + 1`

- [ ] submit 409 回傳 `details.staleItems`
- [ ] DELETE 只下架 current version，不刪除歷史
- [ ] JSON store 測試通過
- [ ] PostgreSQL migration 可套用

## 常見問題

### history 只有一筆

代表資料仍是舊模型，或 PATCH 還在覆蓋同一筆資料。請確認 `updateMenuItem` 是否建立新 row/item。

### current menu 出現多筆同一個 logicalId

代表舊版沒有被設為 `isCurrentVersion: false`。請檢查 update transaction 或 JSON store persist 結果。

### stale submit 沒有 currentPrice

代表後端只用舊版 `id` 查 current menu。現在應該用 `id` 或 `logicalId` 對照 current menu。

### PostgreSQL 啟動失敗，說欄位不存在

請先套用：

```bash
bunx drizzle-kit migrate
```

確認 DB 裡有：

- `logical_id`
- `entity_id`
- `is_current_version`
- `supersedes`
- `created_at`
- `changed_at`
